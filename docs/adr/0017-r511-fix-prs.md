# ADR-0017: PRs that close open findings may merge under R-511

Status: accepted · Date: 2026-10-15 · Issue: #44

## Context
R-511 blocks any merge while a Medium or higher finding is open. Read literally, it also blocks the PRs that fix those findings, which deadlocks the build.

## Decision
While a Medium or higher finding is open, a PR may merge only if all of these hold:
1. It closes at least one finding: an open issue labeled `type:security` and `severity:*` (any severity), named with `Closes #N`.
2. It holds `approved:security` at its head SHA. That approval confirms the fix is complete, not only referenced.
3. It contains only the fix and the records the fix needs (ADRs, docs, tests, status).
4. Every PR below it in a stack is also a fix PR under these terms.
Every other PR waits until no Medium or higher finding is open. `review-gate` and `scripts/phase-gate.mjs` (#14, #16) apply the same reading; the phase gate itself still fails while any such finding is open.

## Consequences
- The veto still stops feature work and launches while risk is open.
- Fix PRs merge first, in stack order.

## Alternatives
- Accept each finding by ADR to unblock: weaker, leaves risk open.
